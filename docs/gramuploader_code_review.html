🔴 Critical Bugs

CRITICAL handlers/__init__.py — FSM handler registration order is broken
manage.register(app) followed by ai.register(app) — both register filters.text & filters.private handlers (FSM). Pyrogram fires the first matching handler only. So manage.py's fsm_text will always intercept text messages, and ai.py's ai_fsm_text will never fire for the STATE_WAIT_HINT state. Same conflict for filters.document — manage.py's fsm_document vs video.py's video upload handler. Fix: Merge all FSM text/document routing into a single handler with a shared state dict.
CRITICAL handlers/video.py — Document FSM conflict
manage.register() registers filters.document & filters.private FSM handler. video.register() also registers filters.video | filters.document as the upload handler. When a user sends a .srt file inside the caption FSM, Pyrogram may route it to the video upload handler instead. Fix: In manage.py's fsm_document, add an early state-check guard. Currently it has one (state != STATE_CAPTION_FILE), but the issue is that both handlers are registered — whichever was registered first wins entirely.
CRITICAL handlers/admin.py — Broadcast sends hardcoded string, not the replied message
broadcast_do callback does: await client.send_message(uid, "📢 Announcement from bot admin.") — completely ignores the original message the admin replied to. The user is told "Reply to a message to broadcast it" but the actual text is never used. Fix: Store the reply message ID before showing confirm dialog, then forward it in the callback.
CRITICAL services/oauth_server.py — flow.fetch_token() is a sync call inside async route
flow.fetch_token(code=code) is a blocking network call inside a FastAPI async route handler. This will block the entire uvicorn event loop during Google token exchange (potentially 300–2000ms). Fix: Wrap with await asyncio.to_thread(lambda: flow.fetch_token(code=code)).

🟠 Bugs / Logic Errors

BUG keyboards.py — upload_confirm keyboard has "Edit Title" button with no handler
Button callback_data=f"upload_edit_title:{upload_id}" is defined in the keyboard, but there is no on_callback_query handler for the pattern ^upload_edit_title:(.+)$ anywhere in the codebase. Clicking it will silently do nothing.
BUG keyboards.py — Admin panel buttons "API Keys" and "Broadcast" have dead callbacks
callback_data="admin_keys" and callback_data="admin_broadcast" buttons exist in the admin panel keyboard, but admin.py has no handlers registered for ^admin_keys$ or ^admin_broadcast$. The broadcast flow only works via the /broadcast command.
BUG handlers/start.py — cb_back_start callback regex mismatch
Handler registered as filters.regex("^back_start$") but keyboard buttons send callback_data="back_start" — this actually matches. However, start.py's cb_manage_open and cb_ai_menu are registered in start.py but use callback_data="mgr_open" and "ai_menu". This works, but these cross-handler callbacks create confusion — if manage.py's handlers fire first, start.py's callbacks for the same data will be shadowed.
BUG services/youtube_uploader.py — API key tracking uses wrong ObjectId
api_key_doc = await apikey_repo.get_active() returns a raw dict (not an APIKey model). Then await apikey_repo.increment_usage(api_key_doc["_id"], UPLOAD_UNITS) — this is correct only if _id exists in the dict. If MongoDB stores the key without _id (e.g. the APIKey.model_dump() result doesn't have _id since it's not in the model), this will raise KeyError. The APIKey Pydantic model has no _id / id field — the _id is auto-assigned by MongoDB but never mapped back. Needs doc.get("_id") guard and the repo's add() should store/return the inserted id.
BUG services/ai_service.py — Whisper audio path replacement is fragile
audio_path = video_path.replace(".mp4", ".wav").replace(".mkv", ".wav") — only handles .mp4 and .mkv. Files downloaded by Pyrogram get random temp names (often without extension). The fallback if audio_path == video_path: audio_path = video_path + ".wav" handles this, but the primary replace logic is misleading and prone to producing wrong paths (e.g. a path like /tmp/downloads/abc.mp4.part.mp4 could produce unexpected results). Use os.path.splitext instead.
BUG handlers/manage.py — Schedule FSM imports datetime twice
Inside fsm_text, the STATE_SCHEDULE branch does from datetime import datetime, timezone — but datetime is already imported at the top of the module as... actually it's NOT imported at the top. The top-level imports are missing datetime. The in-function import works but is inconsistent. More importantly, datetime.strptime can raise ValueError for bad format — this is caught by the outer except Exception, but the error message would be confusing to users. Add format guidance to the message.
BUG database/repositories/upload_repo.py — mutable default argument
async def set_status(self, upload_id, status, extra: dict = {}) — using a mutable default argument {} is a classic Python bug. If the dict is ever mutated inside, it persists across calls. Use extra: dict = None and then extra = extra or {} inside the function.

🔵 Warnings / Design Issues

WARN queue_worker.py — In-memory queue, no persistence on restart
upload_queue: deque = deque() — all queued uploads are lost if the bot crashes or Render restarts. Jobs in PENDING or DOWNLOADING status in MongoDB are never retried on startup. Add a startup recovery: query upload_repo for stuck PENDING/DOWNLOADING jobs and re-enqueue them.
WARN main.py — OAuth server uses threading.Thread with asyncio
Uvicorn (FastAPI) is started in a daemon thread while the bot runs in the main asyncio loop. The OAuth callback handler does await user_repo.set_youtube_token(...) — this is an async Motor call being awaited inside a FastAPI async route, which runs in a different thread's event loop. This will work because FastAPI/uvicorn creates its own event loop, but the Motor client was initialized in the main loop. This is a potential race condition. Better: use asyncio.run_coroutine_threadsafe() or initialize a separate Motor client for the OAuth server.
WARN utils/i18n.py — i18n system loaded but never used in messages
A full locale system exists (utils/i18n.py, locales/en.json, locales/ml.json) and user language settings are stored in MongoDB. But utils/messages.py completely ignores it — all messages are hardcoded in English. The settings UI even lets users pick Malayalam. This feature is 0% wired up.
WARN handlers/video.py — _pending dict never expires
_pending is an in-memory dict of pending confirmations. If a user initiates an upload and never responds (no confirm, no cancel), the entry stays forever. Under heavy use this is a memory leak. Add a TTL — store timestamp alongside the data and clean up entries older than 10 minutes in a background task, or use cachetools.TTLCache.
WARN config.py — ADMIN_IDS can silently be empty list
If ADMIN_IDS env var is empty or unset, ADMIN_IDS = [] silently. No admin will ever be able to use admin commands, and the bot startup will skip the admin notification without any warning. Add a startup validation: if not Config.ADMIN_IDS: log.warning("ADMIN_IDS is empty — no admin access!").

✅ What's Done Well

GOOD Token auto-refresh implemented correctly
youtube_uploader.py checks creds.expired and refreshes using asyncio.to_thread + saves back to DB. Clean pattern.
GOOD Resumable upload with progress callback
MediaFileUpload(resumable=True) with chunked progress is correctly implemented. Upload recovery on failure is possible because of this.
GOOD Rate limiter in middlewares
Clean in-memory rate limiter with sliding window. Applied before all DB operations.
GOOD Clean repository pattern
UserRepository, UploadRepository, APIKeyRepository — well-separated, Motor async, no raw collection calls scattered in handlers.
GOOD Render PORT env var handling
int(os.getenv("PORT") or os.getenv("OAUTH_SERVER_PORT", 8080)) — correctly handles Render's injected PORT variable.
GOOD Whisper RAM guard
psutil.virtual_memory() check before loading Whisper model — prevents OOM crash on small instances.
